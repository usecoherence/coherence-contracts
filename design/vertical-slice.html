1 page summary

One spec. All ACs. Code. Run. Report.

The minimal contract that covers the vertical path end to end and nothing beyond it. Tables are JSONL rows in git. Protobuf describes a row, not an ORM. Everything this path does not need stays outside the slice boundary.

kernel ⊥ core ~150 lines of proto 28 → 14 messages link — the only generic join

02Ingestrepo → branch → file
03LinkAC —verified_by→ file

contracts.jsonl versioned · deterministic order

source of truth (git) artifact bundle (gitignored, inspectable) contract core

In the slice

  • +One spec with all its ACs and an owner.
  • +Ingest a list of repositories and branches from config.
  • +Manual or agent link: AC —verified_by→ code_file.
  • +Deterministic selection: links → run plan.
  • +One behavior: run_tests(files); artifacts in run/.
  • +Report per RunItem; --persist decides what gets published.
  • +Extension example: a Confluence page via persisted_to.

Deliberately deferred

  • −ObjectKindDefinition and Any-envelope: not needed until third-party objects appear at runtime.
  • −Validation protocols: in the slice, validation is tool output plus an exit code.
  • −Entity / Attribute / State / Transition / Invariant — outside the path.
  • −Deep SCIP ingest: tables reserved, links stay at file level.
  • −Multiple behavior engines: one, with a visible extension point.
  • −Jira/GitHub publishers: pattern proven by one Confluence example.

≤ 1 page protobuf

Schema

Three packages, fourteen messages. A table row is a message with a shared RecordMeta; a link between any two rows is one Link.

coherence/kernel/v1/kernel.proto~30 lines
syntax = "proto3";
package coherence.kernel.v1;

// Shared identity and display for any row.
message RecordMeta {
  string id    = 1;  // stable, never reused
  string slug  = 2;  // human handle
  string title = 3;
  string description = 4;
  string status = 5; // draft | active | archived
  int64 created_at_unix_s = 10;
  int64 updated_at_unix_s = 11;

// One directed semantic edge between rows.

}

Decisions that keep the schema small

DecisionWhy
One RecordMeta for all tablesid / slug / title / description / status / time are described once, not in every message.
One Link instead of edge tablesverified_by, depends_on, persisted_to — rows of one shape, without a separate message per relation.
Canonical names are singulartype_from / type_to match table and message names: spec, acceptance_criterion, code_file. One vocabulary instead of two.
No Any and no registriesJSONL is already typed by table name. The kinds registry returns when third-party runtime objects appear.
Extensions are separate packagesConfluence/Jira add tables and link to core via Link. Core stays unchanged.

The package boundary is enforceable: coherence.kernel.v1 does not import coherence.core.v1. This rule is already in AGENTS.md and enforced by the buf plugin.

Result

contracts.jsonlone line = one record
{"table":"spec","id":"spec-001","slug":"specs-as-code","level":"module","status":"active","title":"Specs as code","description":"...","owner_id":"owner-001"}
{"table":"acceptance_criterion","id":"ac-001","spec_id":"spec-001","slug":"ac-jsonl-roundtrip","status":"active","title":"JSONL roundtrip"}
{"table":"owner","id":"owner-001","name":"core"}
  • 1Deterministic order: (table, id). Diffs are readable, merges are predictable.
  • 2Uniqueness: id globally, slug — within a table.
  • 3References are checked on read: owner_id and spec_id must exist.
  • 4Errors are a list of {line, table, id, problem} and exit code 1.

One file is a deliberate start. As volume grows, splitting into contracts/spec.jsonl etc. is a mechanical operation; the schema does not change.

Selection → run plan

Selection is fully deterministic: no LLM at run time. An agent may propose links, but only recorded edges execute.

ruleverified_by
links
  .where(relation_kind == "verified_by")
  .where(source.status == "active")
  .join(acceptance_criterion on from_id)
  .join(code_file on to_id)
  .group_by(ac.id)
plan · 1 spec · 3 AC · 4 files
ACfiles
ac-001e2e/spec.spec.ts · e2e/api.spec.ts
ac-002tests/jsonl_test.go
ac-003tests/report_test.go

ACs with status=archived or links with confidence<1 do not enter the plan automatically. They can be included with an explicit scope filter.

≤ 1 page reporting

Report

human + agent signal

A report is not a log dump but a minimal set of signals: which AC broke, where the code is, what was expected, how to reproduce.

Model

run_tests_reportone row per RunItem
fieldmeaning
run_idwhich run
link_idwhich edge was checked
acceptance_criterion_idwhich AC
code_file_idwhich file was executed
expected / actualexpected and actual
reasonwhy failed/skipped
statusok · failed · skipped

Result

report.jsonone row per RunItem
{
  "run_id": "run-1763550000",
  "link_id": "link-001",
  "acceptance_criterion_id": "ac-001",
  "code_file_id": "file-017",
  "expected": "JSONL roundtrip preserves all ACs",
  "actual": "1 AC lost its spec_id after re-import",
  "reason": "assertion failed at e2e/spec.spec.ts:42",
  "status": "failed"
}

Progressive disclosure

  1. 1Broken AC: text and id. Most important first.
  2. 2File and line range; snippet behind a spoiler.
  3. 3Context: neighboring symbols, other files, neighboring ACs — collapsed.
  4. 4Reproduction: screenshot / recording / trace + re-run command.

Principle: the report should read in 30 seconds and expand to full debug context only on demand. Evidence is pre-processed into these four levels.

Persist policy

The same run behaves differently depending on context and flag. Toggle:

Whatlocalci+ --persist

report rows in contracts.jsonlnoyesyes
external evidence copiesnoyesyes
PR comment / statusnoyesyes

local default: artifacts sit nearby, but nothing is published.
